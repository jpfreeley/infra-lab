# Epic E08: Orchestration (SQS + Step Functions)

## Overview

Epic E08 implements the message-driven orchestration layer. SQS queues decouple the API
from worker processing, and Step Functions orchestrates multi-step job lifecycles with
routing, retry, and notification.

---

## Stories Completed

### E08-S001: SQS Queues per Worker Tier + DLQs

- **Nano queue**: 2-min visibility timeout, 3 retries, 14-day retention
- **Medium queue**: 5-min visibility timeout, 3 retries, 14-day retention
- **XLarge queue**: 15-min visibility timeout, 2 retries, 14-day retention
- **Ordered (FIFO)**: content-based deduplication, message group ordering
- Each queue has a dedicated DLQ with redrive allow policy

---

### E08-S002: Step Functions State Machine (Job Lifecycle)

State machine: `infra-lab-dev-job-orchestrator`

Flow: ValidateInput → RouteByTier → SendToQueue → WaitForCompletion → CheckStatus → Notify

- Routes jobs to the correct tier queue based on `$.tier` field
- X-Ray tracing enabled
- CloudWatch logging (ERROR level in dev, ALL in prod)
- IAM role scoped to SQS send + X-Ray

---

### E08-S003: Idempotency Keys + Dedup Strategy

- FIFO queue (`-ordered.fifo`) uses content-based deduplication
- `deduplication_scope = messageGroup` — dedup per message group, not queue-wide
- `fifo_throughput_limit = perMessageGroupId` — high throughput per group
- Standard queues rely on application-level idempotency (worker responsibility)

---

### E08-S004: Worker Shutdown Handling

Architecture documented in visibility timeout configuration:

- Visibility timeout >= expected processing time + SIGTERM grace period (30s)
- `max_receive_count` limits retries before DLQ (prevents poison pill loops)
- Workers must extend visibility timeout for long-running jobs
- ECS task `stopTimeout` should be set to match SIGTERM grace period

## Modules Created

### `infra/modules/sqs_queue`

- Standard or FIFO queue with configurable parameters
- Automatic DLQ creation with redrive policy
- SSE-SQS encryption (CMK optional)
- Long polling enabled by default (20s)
- Outputs: queue URL/ARN/name, DLQ URL/ARN

### `infra/modules/step_function`

- Standard or Express state machine
- IAM role with configurable policy + CloudWatch logs permissions
- CloudWatch log group with configurable retention
- X-Ray tracing enabled by default
- Outputs: state machine ARN, role ARN, log group name

---

## Architecture Decisions

1. **Queue per tier**: Each worker tier gets its own queue. This allows independent
   visibility timeout tuning and prevents fast nano jobs from being blocked behind
   slow xlarge jobs.

1. **DLQ after N retries**: Messages that fail repeatedly go to DLQ for investigation.
   This prevents infinite retry loops and poison pill scenarios.

1. **FIFO for ordered work**: When job ordering matters (sequential processing),
   use the FIFO queue. Content-based dedup eliminates duplicate submissions.

1. **Step Functions for orchestration**: Complex multi-step workflows use Step Functions
   instead of chaining SQS messages. Provides visibility, retry logic, and timeout
   handling without custom code.

1. **Visibility timeout strategy (S004)**: Set to processing_time + 30s SIGTERM grace.
   Workers should call `ChangeMessageVisibility` for jobs that run longer than expected.
