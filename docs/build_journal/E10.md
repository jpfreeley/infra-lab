# Epic E10: Observability

## Overview

Epic E10 establishes CloudWatch-native observability for the platform.
Dashboards provide visibility into queue depth, latency, errors, and resource utilization.
Alarms trigger on anomalous conditions with SNS notification.

OTel collector is deferred to prod deployment (adds sidecar compute cost).

---

## Stories Completed

### E10-S001: Observability Strategy (OTel Deferred)

**Decision**: OTel collector as ECS sidecar adds ~$15/mo compute in dev.
Using CloudWatch-native metrics, logs, and X-Ray tracing instead.

When to add OTel:

- Production deployment with distributed tracing requirements
- When vendor-neutral telemetry pipeline is needed (Datadog, Grafana, etc.)

CloudWatch provides sufficient observability for a single-environment lab.

---

### E10-S002: Structured JSON Logging Standard

Architecture documented (not enforced via infra — app-level concern):

- All services emit JSON logs to CloudWatch via `awslogs` driver
- Standard fields: `timestamp`, `level`, `service`, `trace_id`, `tenant_id`, `job_id`
- CloudWatch Log Insights queries parse JSON automatically
- Log groups already created by ECS service module with per-service naming

---

### E10-S003: Dashboards

Dashboard: `infra-lab-dev-operations`

Widgets:

- ECS CPU Utilization (API service)
- ECS Memory Utilization (API service)
- SQS Queue Depth (all tiers)
- SQS DLQ Messages (failure indicator)
- ALB Request Count + 5xx Errors
- ALB Target Response Time (p95)

---

### E10-S004: Alarms

| Alarm | Condition | Action |
| --- | --- | --- |
| API CPU High | CPU > 85% for 5 min | SNS |
| API 5xx High | 5xx > 10 in 5 min | SNS |
| DLQ Messages | DLQ > 0 messages | SNS |
| Queue Backlog | Queue > 100 msgs for 10 min | SNS |

All alarms notify the `infra-lab-dev-alarms` SNS topic.
Subscribe email/Slack/PagerDuty as needed.

---

## Modules Created

### `infra/modules/cloudwatch_dashboard`

- Single dashboard resource with JSON body
- Outputs: dashboard ARN, name

### `infra/modules/cloudwatch_alarms`

- Creates alarms from a list of definitions (for_each)
- Configurable alarm/OK actions (SNS)
- Outputs: map of alarm name → ARN
