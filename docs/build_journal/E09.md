# Epic E09: Secrets + PKI + mTLS

## Overview

Epic E09 establishes secrets management for the platform. Due to the high cost of
AWS Private CA ($400/mo per CA), only Secrets Manager (S001) is deployed.
PKI and mTLS stories (S002-S005) are documented as architecture decisions for
future implementation when service-to-service auth is required.

---

## Stories Completed

### E09-S001: Secrets Manager Bootstrap + Access Policies

- **Module**: `infra/modules/secrets_manager` — reusable secret with resource policy,
  optional rotation, KMS encryption
- **Secrets deployed** (with placeholder values):
  - `infra-lab-dev/api/database-url` — API DB connection (JSON)
  - `infra-lab-dev/worker/database-url` — Worker DB connection (JSON)
  - `infra-lab-dev/app/config` — Shared app secrets (JWT key, webhook)
- Access controlled via ECS task execution role (already grants
  `secretsmanager:GetSecretValue` scoped to `infra-lab-dev/*`)
- 7-day recovery window (prevents accidental permanent deletion)
- Values managed externally after initial bootstrap (lifecycle ignore)

---

## Stories Deferred (Architecture Decisions)

### E09-S002: AWS Private CA (DEFERRED — Cost)

**Decision**: AWS Private CA costs $400/mo per CA. A root + issuing CA = $800/mo.
This is not justified for a lab environment.

**When to implement**: When the platform has production workloads requiring
service-to-service mTLS authentication.

**Architecture when ready**:

- Root CA in Security OU account (offline, 10-year validity)
- Issuing CA in workload account (3-year validity, issues short-lived certs)
- Certificate revocation via CRL published to S3

---

### E09-S003: Share Private CA via RAM (DEFERRED)

**Depends on**: S002 (Private CA must exist first)

**Architecture**: Use AWS RAM to share the issuing CA from security account
to workload accounts. Services request certs via ACM without cross-account roles.

---

### E09-S004: ACM Private Cert Issuance (DEFERRED)

**Depends on**: S002, S003

**Architecture**: ECS services request short-lived certificates (30 days) from
the shared issuing CA. Certs auto-renewed by ACM. Stored in task container
via sidecar or init container.

---

### E09-S005: mTLS Enforcement (DEFERRED)

**Depends on**: S002, S003, S004

**Architecture**: ALB configured with mutual TLS. Client certs required for
the Results Ingestion API. Trust store references the issuing CA certificate.

---

## Module Created

### `infra/modules/secrets_manager`

- Secret with configurable KMS encryption
- Optional initial value (ignored after first create)
- Optional resource policy for cross-account/cross-service access
- Optional rotation configuration (Lambda ARN + rotation interval)
- Outputs: secret ID, ARN, name

## Cost Notes

| Resource | Monthly Cost |
| --- | --- |
| Secrets (3 secrets × $0.40) | ~$1.20 |
| API calls | ~$0 (low volume) |
| **Total** | **~$1.20/mo** |

Compared to Private CA ($800/mo), this approach saves ~$799/mo.

---

## Security Model

```text
ECS Task → Task Execution Role → secretsmanager:GetSecretValue
                                 (scoped to infra-lab-dev/*)

Secret Resource Policy → (optional) restrict to specific roles/accounts
```

Secrets are referenced in ECS task definitions via the `secrets` block,
which injects them as environment variables at container start.
