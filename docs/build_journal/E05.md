# Epic E05: Networking (Dual VPC per env)

## Overview

Epic E05 implements the complete networking layer for the infra-lab platform.
Each environment (dev, staging, prod) gets two VPCs: a Control VPC for
management/orchestration workloads and an Execution VPC for tenant/worker
workloads with restricted egress. The design enforces network segmentation,
private connectivity via VPC endpoints, and controlled lateral movement
via NACLs and security groups.

### E05-S020: Execution VPC NACL (RFC1918 Egress Denial)

### E05-S025: Security Group Least-Privilege Matrices

- Control VPC:
  - ALB SG: ingress 443 from internet, egress 8080 to ECS SG
  - ECS SG: ingress 8080 from ALB, 443 from Execution VPC; egress 443 to endpoints, 5432 to RDS
  - RDS SG: ingress 5432 from ECS SG only; no egress
- Execution VPC:
  - ECS SG: ingress 8080 self; egress 443 to endpoints/internet, 5432 to RDS
  - RDS SG: ingress 5432 from ECS SG only; no egress
- Cross-SG rules implemented via `aws_security_group_rule` to avoid cycles

## Architecture Decisions

### Dual VPC Model

Two VPCs per environment provides strong network isolation between control
plane (orchestration, API, management) and execution plane (tenant workloads).
This prevents compromised worker tasks from accessing management infrastructure.

### VPC Peering vs Transit Gateway

VPC peering chosen for simplicity in single-account model. Transit Gateway
would be appropriate when expanding to multi-account deployments. Peering
has no bandwidth limits and lower latency.

### NAT Gateway Strategy

- Dev/staging: Single NAT saves ~$65/month per environment
- Prod: Per-AZ NAT ensures no cross-AZ traffic and survives AZ failures
- All environments have internet egress for patch downloads and external APIs

### NACL vs Security Group Enforcement

- NACLs: Stateless deny rules for broad RFC1918 blocking (defense in depth)
- Security Groups: Stateful allow rules for application-level access control
- Both layers enforced simultaneously (belt and suspenders)

### VPC Endpoint Strategy

Interface endpoints placed only in Control VPC to minimize cost. Execution VPC
gets S3 Gateway (free) and Logs Interface (required for container logging).
All other API calls from Execution VPC route through NAT or peered Control VPC.
