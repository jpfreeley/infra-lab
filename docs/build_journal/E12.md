# Epic E12: Reliability + Ops + Compliance

## Overview

Epic E12 establishes backup automation, incident response procedures, disaster recovery
strategy, and SOC2 compliance evidence mapping. This is the final epic in the
infra-lab platform build.

---

## Stories Completed

### E12-S001: AWS Backup Policies for RDS

- **Backup vault**: `infra-lab-dev-backup-vault`
- **Backup plan**: Daily (3 AM, 7-day retention) + Monthly (1st, 35-day retention)
- **IAM role**: Dedicated backup role with AWS managed policies
- **Selection**: Tag-based (`Backup=true`) — commented out in dev since clusters
  are frequently stopped. Enabled in prod.

## Architecture Decisions

1. **Tag-based backup selection**: Resources opt-in to backup via `Backup=true` tag.
   This prevents backup attempts on stopped clusters and allows per-resource control.

1. **Dev vs Prod retention**: Dev gets 7/35 day retention (cost optimization).
   Prod will get 35/365 days (compliance requirement).

1. **No backup selection active in dev**: Aurora clusters are frequently stopped.
   AWS Backup would fail on stopped clusters, creating noise. Enable when clusters
   are running consistently.

1. **SOC2 evidence is documentation**: The controls are already deployed (E01-E11).
   E12 maps them to audit criteria so evidence collection is straightforward.
