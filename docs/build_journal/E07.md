# Epic E07: Data Plane (Aurora + RDS Proxy + S3)

## Overview

Epic E07 implements the data layer for the platform. Each VPC plane (control + execution)
gets its own Aurora Serverless v2 cluster with RDS Proxy for connection pooling.
An S3 evidence bucket provides durable object storage for processing outputs.

---

## Stories Completed

### E07-S001: Aurora Serverless v2 (Postgres) in Control VPC

- Aurora PostgreSQL 15.4, Serverless v2 (0.5-4 ACU in dev)
- Storage encrypted with KMS
- RDS-managed master password (Secrets Manager)
- PostgreSQL logs exported to CloudWatch
- `pgaudit` and `pg_stat_statements` preloaded for compliance

---

### E07-S002: RDS Proxy with Secrets Manager Auth

- Proxy per cluster (control + execution)
- TLS required for all connections
- Connection pool: 80% max connections, 50% idle, 120s borrow timeout
- IAM role reads secrets from Secrets Manager
- Decouples ECS task scaling from DB connection limits

---

### E07-S003: DB Parameter Groups for RLS-safe Pooling

- `rds.force_ssl = 1` (enforce encrypted connections)
- `rds.logical_replication = 1` (future CDC support)
- `shared_preload_libraries = pgaudit,pg_stat_statements`
- `pgaudit.log = ddl,role` (audit DDL and role changes)
- RDS Proxy session pinning disabled (compatible with RLS via `SET ROLE`)

---

### E07-S004: Schema Migrations + Role Separation

Architecture decision documented (not implemented as Terraform):

- **Owner role** (`dbadmin`): DDL operations, schema migrations
- **App role** (`app_rw`): DML only, used by ECS tasks via RDS Proxy
- **Read role** (`app_ro`): SELECT only, for reporting/analytics
- Migrations run via CI/CD pipeline (future story) using the owner role

---

### E07-S005: S3 Evidence Bucket

- Per-environment bucket: `infra-lab-dev-evidence`
- SSE-KMS encryption with dedicated key (auto-rotation enabled)
- 90-day lifecycle expiration in dev (365 days in prod)
- Bucket hardening via `s3_secure_bucket` module (public access blocked, versioning)

## Modules Created

### `infra/modules/aurora_cluster`

- Aurora Serverless v2 with configurable ACU min/max
- RDS-managed master password (Secrets Manager integration)
- Cluster parameter group with pgaudit, SSL enforcement, logical replication
- Outputs: cluster endpoints, port, database name, master secret ARN

### `infra/modules/rds_proxy`

- RDS Proxy with Secrets Manager auth
- Configurable connection pool settings
- IAM role for secret access with KMS decrypt
- Outputs: proxy endpoint, ARN

## Architecture Decisions

1. **Serverless v2 over provisioned**: Scales ACUs with load, costs $0 when idle
   at 0.5 ACU min. Eliminates capacity planning for dev/staging.

1. **RDS Proxy mandatory**: ECS tasks create many short-lived connections.
   Without proxy, Aurora would hit connection limits during scaling events.
   Proxy pools and reuses connections transparently.

1. **Separate clusters per plane**: Control DB holds orchestration state (API).
   Execution DB holds tenant workload data (workers). Isolation prevents
   noisy-neighbor issues and enables independent scaling.

1. **RLS-safe pooling**: `session_pinning_filters = []` means no pinning.
   Combined with `SET ROLE` in app code, this enables row-level security
   without breaking connection reuse.

1. **Managed secrets**: `manage_master_user_password = true` delegates password
   rotation to RDS, stored in Secrets Manager. No static credentials anywhere.

## Cost Notes (Dev Idle)

| Resource | Idle Cost |
| --- | --- |
| Aurora control (0.5 ACU min) | ~$44/mo |
| Aurora execution (0.5 ACU min) | ~$44/mo |
| RDS Proxy (2 instances) | ~$22/mo |
| S3 evidence bucket | ~$0 (storage only) |
| KMS key (evidence) | ~$1/mo |
| **Total** | **~$111/mo** |

Note: Aurora Serverless v2 minimum is 0.5 ACU ($0.12/ACU-hour × 730 hours = $43.80).
